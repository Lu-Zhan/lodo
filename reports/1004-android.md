# Android 功能同步报告

日期:2026-10-05　　范围:`android/`(对齐 iOS 现状;共享相关按要求暂停)

## 结论

- 安卓端从原来的「任务 / 已完成 / 记忆」三个 tab,扩到和 iOS 一样的 **12 个平级页面**:
  - 总览、任务、日历、倒数、记忆、人脉、资产、健康、旅行、菜单、新闻、AI 助手。
- AI 助手改成和 iOS 一样的 **单一持续对话**,`command` 协议对齐 iOS。
- UI 换成 **Material 3 Expressive**:
  - 模态 / 常驻宽导航栏;
  - Material You 动态取色 + 六档强调色;
  - 大圆角分组卡片;
  - 各页底部常驻「问问 AI」。
- 单测 **123/123 通过**,其中新增 41 个(AI 协议解析 + 倒数日/收支/旅行/新闻/菜单/健康纯逻辑)。
- 在手机和平板模拟器上逐页跑过,**真发 AI 请求**做了端到端验证(见「三、怎么验证的」)。
- 调试包:`releases/lodo-android-2.0-1004-debug.apk`(versionCode 2,minSdk 31,约 107 MB)。
- **尚未提交到 git。**

## 一、构建与设计

### 构建链升级

| 项 | 原来 | 现在 |
|---|---|---|
| AGP / Gradle | 8.7.3 / 8.11.1 | 8.13.2 / 8.14.3 |
| Kotlin / KSP | 2.1.0 / 1.0.29 | 2.3.20 / 2.3.12 |
| Compose BOM | 2024.12.01 | 2026.03.00 |
| Material 3 | 1.3.x | **1.5.0-alpha14** |
| Room | 2.6.1 | 2.8.4 |
| compileSdk / targetSdk | 35 | 36 |

为什么 Material 3 用 alpha 版:

- 1.4.0 稳定版里 Expressive API(`MaterialExpressiveTheme` 等)是内部可见的,用不了。
- 更新的 BOM(2026.09)要求 AGP 9 + compileSdk 37,和现有工程不兼容。
- 1.5.0-alpha14 是最后一个只依赖 Compose UI 1.8+ 的 Expressive 公开版本。

新增依赖:

- ML Kit 文字识别(中 / 日 / 韩,模型打包进 APK,不依赖 Play 服务)。
- Health Connect client 1.1.0。

### 设计(Material 3 Expressive)

- **导航**
  - 手机:左上角 ☰ 拉出模态宽导航栏(`ModalWideNavigationRail`,取代旧抽屉),对应 iOS 的侧栏抽屉。
  - 宽屏(≥600dp):常驻 `WideNavigationRail`,☰ 收起 / 展开。
  - 设置在导航栏最下面。
- **主题**
  - 默认「跟随壁纸」(Material You 动态取色)。
  - 设置里可换成 iOS 同名的六档强调色(赤陶 / 靛蓝 / 靛紫 / 松绿 / 玫红 / 石墨),明暗两套。
  - 状态色单独一套(逾期红 / 完成绿 / 警示琥珀),不跟强调色走,同 iOS `LodoColor`。
- **页面**
  - 平级页面统一用 `LodoPage`:顶栏 + 底部「问问 AI」胶囊,点了从底部拉起 AI 助手,带页面焦点。
  - 页面上不放「+」,新建一律走 AI,同 iOS。
  - AI 接不了的入口留在右上角:倒数日新建、资产里的收入/支出/信用卡、菜单拍照、旅行导入订单、人脉导入通讯录等。
- **其他**:深色模式、平板宽屏都跑过。

### 有意不做 / 暂停

- **共享**:旅行共享、资产台账共享(iOS 走 CloudKit CKShare),按要求先停。安卓也没有对应的 iCloud 同步。
- **锁屏小组件、iCloud 诊断、Watch**:平台差异。原有桌面小组件保留不动。

### 旅行地图(10-05 补做)

- **地图**:osmdroid + OpenStreetMap 标准瓦片,不要 key。
  - 安卓没有 MapKit 那样的系统地图控件;Google Maps SDK 要 API key。
  - CARTO 瓦片试过,现在要 key、带水印,所以换回 OSM 标准瓦片。深色模式把瓦片反色。
- **地名查坐标**:OpenStreetMap Nominatim,逻辑移植自 iOS 的 `PlaceRegion` / `OSMGeocode` / `TravelDestination`。
  - 先认出这趟旅行的国家;认不出就验一个城市锚点、用锚点所在的国家;都认不出就不查,并提醒去填城市和国家。
  - 只认这个国家的结果,名字要对得上 60% 以上,同名地点按知名度挑,有锚点时优先 200 公里内。
  - 繁→简转换后再比名字(安卓用 ICU 的 Hant-Hans)。不转的话「筑地场外市场」对不上 OSM 里的「築地場外市場」,实测过。
  - 住宿先查酒店本身(「住新宿一带」→「新宿」),再退回它填的地点。
- **路线**:选某一天时,画「前一晚的酒店 → 当天地点(按时间编号)→ 当晚的酒店」。
  - 先请求 OSRM 真实路线:一两公里内步行,再远驾车;备选路线里在耗时不超过最快 20% 的范围内取最短。
  - 规划出来的路线缓存到 `travel-routes.json`,地点没动就不再请求;规划不出来的那段画虚线直线。
  - 选「全部」时只画点,不连线。
- **交互**:
  - 手机上地图在上、面板在下,右下角可以放大成整页地图;宽屏是左面板、右地图。
  - 点一行,地图飞到那个点并选中;还没坐标时当场查一次,查不到给「在地图上标注」。
  - 放针模式:针钉在屏幕正中,拖动地图对准后确认。
  - 打开详情时自动补没坐标的地点(一次最多 25 条)。
  - 右上角菜单「刷新地点位置」:全部重查,分开报「更新 / 没变 / 没搜到」几个。
  - 行程项详情里有「刷新位置」「在地图上标注」;行上没坐标的标「无地点」。
- **规矩**:Nominatim / OSRM 都是社区服务。请求带可识别的 User-Agent、串行、每秒最多 1 次;发出去的只有地名 + 国家码 / 两端坐标。
- **没做**:iOS 的 AI 校准选点(`calibratePlaces`)、苹果地名搜索那一路、交通类(机场)的点。
- **实测**:通过 AI 记下「东京三日」后,6 个地点(含住宿)全部定位到东京的正确位置;第 2 天的步行路线正常画出;点行飞过去、放大地图都正常。

  - 新增 `ai/AgentProtocolTest`:提问卡、漏外壳兜底、工具误塞进 actions、倒数日 / 资产 / 订阅解析、id 规范化、规划年份校正与 record、edit_trip 去重、混合时问答类丢弃、张冠李戴防护、auto_memorize 门控。

- **模拟器手动验证**,手机 Pixel 6 / Android 15 + 平板 Pixel Tablet,真发 DeepSeek 请求:
  - 「明天下午三点开会,另外记个倒数日:12月20号考研」:一句话同时出任务卡和倒数日卡,倒数页 AI 一句话正常。
  - 「帮我规划东京三天,11月10号出发」:规划卡 → 写入行程 → 跳转小条进到旅行详情,按天分组、住宿排在每天最后。
  - 「东京三日第二天的秋叶原换成台场」:先 `read_trip` 再 `edit_trip`,可撤销。
  - 「记一下招行存款32万,再订阅少数派」:资产 + 订阅一张卡;真的抓到少数派 feed,新闻页有文章;打开文章抓到全文并自动 AI 总结。
  - 菜单:一段被输入法搅乱的居酒屋菜单文字,AI 整理出 4 道菜(分类、中文译名、简介、JPY 价格);勾选、合计正常。
  - 日历:用 `content insert` 塞了 3 条系统日程,授权后列表 / 月格正常。
  - Health Connect:授权页能拉起、7 项读权限都列出,授权后进入数据页。模拟器没有健康数据,显示的是空态。
  - 深色模式、平板宽屏 12 页逐个打开,无崩溃。
  - 平板一开始崩过一次,原因是宽导航栏上挂了 `verticalScroll`,已修。
- **内置 key**(同 iOS「使用内置 API Key」):
  - DeepSeek key 写在 gitignored 的 `android/local.properties`(`lodo.deepseekKey=…`),构建时进 `BuildConfig`,**仓库里没有真实值**。
  - 设置 → AI 里有「使用内置 API Key」开关,默认开;没配 `local.properties` 的人构建出来就是没有内置 key,照常自己填。
  - 另有仅可调试版本才认的 intent extra `debugApiKey`,可以临时往本机设置里写 key。

## 四、已知问题与没验证的

1. **真机没验证。** 以下都只在模拟器上跑过:
   - 拍照(相机)、ML Kit 对真实菜单照片的识别效果;
   - Health Connect 的真实数据读取;
   - 倒数日 / 信用卡提醒到点弹通知。
2. **新页面的文案没进 `i18n/strings.csv`。**
   - 现在就地写成中英一对(`ui/L.kt`),跟应用内语言走。
   - 老页面仍是生成的 `R.string`。
   - 以后要统一的话,把 `L("…","…")` 迁进 csv。
3. **应用内语言的修复。**
   - 原来 `AppCompatDelegate.setApplicationLocales` 在 `ComponentActivity` 上不生效:实测 `get-app-locales` 为空,系统是英文时界面一直跟系统走。
   - 现在 Android 13+ 直接调 `LocaleManager`,12 用 `attachBaseContext` 覆盖。
   - 同时把 JVM 默认 locale 设成应用语言,让星期、月份名跟着走。
4. **AI 助手的局限。**
   - 没有流式输出,长回复要等整段返回。
   - 规划卡更新后列表不会自动滚到最底下的跳转小条。
5. **日历只读。** 没做 iOS 的双向同步(任务镜像进 lodo 日历);视图少了三日和全年。
6. **调试包体积约 107 MB。**
   - 主要是未混淆的 dex(含 material-icons-extended)和 OCR 原生库。
   - 已只保留 arm64-v8a / x86_64 两种 ABI。
   - 正式发版开 R8 会小很多。

## 五、安装

```bash
adb install -r releases/lodo-android-2.0-1004-debug.apk
```

- 联网搜索要另填 Tavily key。
